## 摘要
三维高斯泼溅（3DGS）能够实现实时的全新视角合成，但在高分辨率下GPU上仍受限制。通过分阶段的Roofline特征分析，我们识别出两个不同的硬件瓶颈：全局内存流量主导前端，而指令吞吐量限制光栅化。在此分析的指导下，我们开发了RoofGS，一个应用瓶颈特定优化而非通用内核加速的渲染框架。对于内存受限的前端，我们设计了一种分辨率自适应的量化深度排序键，将每个键压缩至32位。对于计算受限的光栅化器，我们引入了一种范围感知的位级快速指数近似，针对不透明度剔除后的有界指数范围进行定制，并推导了每像素误差界限。这两种核心技术辅以额外优化（内核融合、紧凑属性存储、剔除、双像素评估），进一步减少内存流量并提升指令级并行性。实验表明，在RTX 4090上，RoofGS在4K分辨率下实现了相对于3DGS的10.1倍端到端加速，吞吐量从61 FPS提升至616 FPS，仅损失0.028 dB的PSNR。

## Abstract
3D Gaussian Splatting (3DGS) enables real-time novel-view synthesis but remains limited on GPUs at high resolutions. Through a stage-wise Roofline characterization, we identify two distinct hardware bottlenecks: global memory traffic dominates the front end, whereas instruction throughput limits rasterization. Guided by this analysis, we develop RoofGS, a rendering framework that applies bottleneck-specific optimizations rather than generic kernel acceleration. For the memory-bound front end, we design a resolution-adaptive quantized depth sorting key that compresses each key to 32 bits. For the compute-bound rasterizer, we introduce a range-aware bit-level fast exponential approximation tailored to the bounded exponent range after opacity culling, with a derived per-pixel error bound. These two core techniques are complemented by additional optimizations (kernel fusion, compact attribute storage, culling, dual-pixel evaluation) that additionally reduce memory traffic and improve instruction-level parallelism. Experiments show that RoofGS achieves a 10.1$\times$ end-to-end speedup over 3DGS at 4K on an RTX 4090, increasing throughput from 61 to 616 FPS, with only a 0.028 dB PSNR loss.

## 1. 论文的核心问题与整体含义

- **研究动机**：3D Gaussian Splatting（3DGS）能够实现实时新视角合成，但在高分辨率（如 4K）下仍受 GPU 硬件瓶颈限制，难以满足 AR/VR、游戏、机器人感知等实时应用需求。
- **核心问题**：现有加速工作多采用“逐阶段/逐内核优化”思路，例如用 Tensor Core 加速光栅化、或用剪枝减小前端开销，但缺乏对整条渲染流水线硬件瓶颈的全局判断，局部加速未必能转化为端到端收益。
- **关键观察**：作者通过分阶段 Roofline 模型分析发现，3DGS 渲染流水线中存在两类本质不同的硬件瓶颈：
  - **前端**（投影、复制、深度排序等）主要受全局内存带宽限制，算术强度远低于 Roofline 拐点；
  - **光栅化阶段**主要受指令吞吐量/计算吞吐限制，属于计算密集型。
- **整体含义**：不应采用“一刀切”式统一优化，而应根据每个阶段的硬件瓶颈分别设计优化策略，从而实现真正端到端的加速。

## 2. 方法论：核心思想与关键技术

### 核心思想

- 提出 **RoofGS** 渲染框架，以 Roofline 模型为指导，将优化分为两类：
  - **内存受限阶段**：优先减少全局内存流量；
  - **计算受限阶段**：优先降低指令开销并提升指令级并行性（ILP）。

### 前端（内存受限）优化

1. **紧凑属性存储**
   - 球谐系数（SH）采用 **INT8 量化**，且按 SH 阶数 d 和颜色通道 c 分别设置独立对称缩放尺度，避免单一共享尺度导致低频系数主导、高频系数量化粗糙的问题。
   - 旋转、缩放、不透明度等几何属性使用 **FP16**，三维均值保留 FP32 以保证投影精度。
   - 每个高斯属性占用从 236 字节降至约 96 字节，减少约 59.3% 的内存流量。

2. **分辨率自适应 32 位量化排序键**
   - 传统排序键为 64 位（32 位 tile ID + 32 位浮点深度），需要 8 次基数排序 pass。
   - RoofGS 将排序键压缩为 32 位：高位存放 tile 索引，低位存放量化深度。
   - 位数分配随分辨率/tile 数量动态调整，例如 1080p 下 tile 索引占 13 位，深度占 19 位。
   - 量化深度公式为：

     \[
     q_d = \text{clamp}\left(\left\lfloor \frac{d - z_{\text{near}}}{z_{\text{far}} - z_{\text{near}}} (2^{b_d} - 1) \right\rfloor, 0, 2^{b_d}-1\right)
     \]

   - 该设计同时减小 `S_kv` 和 `N_pass`，显著降低排序内存流量。

3. **前端内核融合**
   - 将预处理、tile 复制、排序键生成合并为单个 kernel。
   - 中间结果保留在寄存器/共享内存中，避免多次全局内存往返。
   - 采用块级前缀和与单次全局原子操作完成重复实例分配。
   - 结合 SpeedySplat 的裁剪策略，剔除贡献可忽略的高斯，减少复制和排序条目数。

### 光栅化（计算受限）优化

1. **双像素评估与 ILP 提升**
   - 将高斯指数项的二次型展开，将像素相关项与高斯相关项分离，把 `-0.5` 和 `log o` 折叠进系数中：

     \[
     P(x,y) = C_1 x^2 + C_2 xy + C_3 y^2 + C_4 x + C_5 y + C_6
     \]

   - 每个线程处理垂直相邻的两个像素 `(x,y)` 和 `(x,y+1)`，共享同一份高斯属性加载。
   - 第二个像素的指数值可由第一个像素增量推导：

     \[
     P(x,y+1) = P(x,y) + C_2 x + C_3(2y+1) + C_5
     \]

   - 这样减少了内层循环中的坐标减法、临时寄存器占用和共享内存访问。

2. **范围感知的位级快速指数近似**
   - 经过不透明度剔除后，指数范围被限制在 `[−ln 255, 0] ≈ [−5.541, 0]`。
   - 采用 Schraudolph 的位级近似：

     \[
     I(P) = \lfloor P \cdot 2^{23} \cdot \log_2(e) + 2^{23}(127 - \sigma) \rfloor,\quad \hat{\exp}(P) = \text{reinterpret\_float}(I(P))
     \]

   - 该近似将 `exp` 替换为少量算术与位操作，降低了特殊函数单元（SFU）压力。
   - 作者推导出在给定有界指数范围内，相对误差 `ε_max ≈ 0.03`，并给出每像素颜色误差界限为 `|ΔC|∞ ≤ ε_max`，且与混合高斯数量无关。
