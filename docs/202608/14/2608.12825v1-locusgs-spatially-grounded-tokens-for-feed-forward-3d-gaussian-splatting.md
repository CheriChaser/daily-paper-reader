## 摘要
近期基于查询的前馈3DGS方法使用可学习查询来表示场景，每个查询聚合多视角证据并解码一组高斯。理想情况下，不同查询应专注于场景中连贯的局部区域。然而，我们观察到从同一查询解码出的高斯常常散布在遥远的场景区域，导致查询级空间连贯性弱，并与场景结构对齐不良。我们将此行为归因于现有高斯查询的纯潜在表示。为解决这一局限，我们引入了LocusGS，为每个高斯查询增加一个由中心和支撑半径组成的3D锚定状态。该锚定状态在解码器层间逐步细化，并贯穿查询交互、多视角特征聚合和高斯生成。具体而言，锚到射线的几何偏置引导每个查询关注空间相关的图像观察，而以锚为中心的解码则将其高斯组织在局部区域内。在新视角合成基准上的实验表明，在相同高斯预算下，LocusGS相比基于查询的高斯令牌基线提高了渲染质量。进一步分析显示，学习到的锚形成了连贯的空间布局，并导致更结构化的高斯分布，证明显式锚定状态改善了空间组织。我们的项目页面：https://leo-frank.github.io/LocusGS_viewer。

## Abstract
Recent query-based feed-forward 3DGS methods represent a scene using learnable queries, each aggregating multi-view evidence and decoding a group of Gaussians. Ideally, different queries should specialize in coherent local regions of the scene. However, we observe that Gaussians decoded from the same query often scatter across distant scene regions, resulting in weak query-level spatial coherence and poor alignment with the scene structure. We attribute this behavior to the purely latent representation of existing Gaussian queries. To address this limitation, we introduce LocusGS, which augments each Gaussian query with a 3D anchor state consisting of a center and a support radius. The anchor state is progressively refined across decoder layers and is used throughout query interaction, multi-view feature aggregation, and Gaussian generation. Specifically, an anchor-to-ray geometric bias guides each query toward spatially relevant image observations, while anchor-centered decoding organizes its Gaussians within a local region. Experiments on novel view synthesis benchmarks show that LocusGS improves rendering quality over query-based Gaussian token baselines under the same Gaussian budget. Further analysis shows that the learned anchors form coherent spatial layouts and lead to more structured Gaussian distributions, demonstrating that explicit anchor states improve the spatial organization. # LocusGS 论文总结

## 1. 核心问题与整体含义

- **研究背景**：前馈 3D Gaussian Splatting（3DGS）旨在从稀疏多视角图像直接预测三维高斯场景表示，避免逐场景优化。其中，查询式（query-based）方法使用固定数量的可学习查询（query/token）聚合多视角信息，并解码为一组高斯，从而将高斯数量与图像分辨率、视角数量解耦。
- **核心问题**：现有查询式方法中，每个查询由纯潜在特征表示，缺乏显式的三维空间状态。这导致同一查询解码出的高斯常常分散在场景中相距较远的区域，造成查询级空间连贯性弱、与场景结构对齐不良，即空间特化不足。
- **整体含义**：论文提出通过为每个查询引入显式 3D 锚点（anchor）状态，将隐式查询转化为“空间上有根据”的查询，从而提升前馈 3DGS 的渲染质量和空间组织性，使场景表示更结构化和可解释。

## 2. 方法论

- **核心思想**：为每个高斯查询附加一个 3D 锚点状态，由锚点中心 μ 和支撑半径 r 组成。锚点在解码器各层中逐步细化，并用于：
  - 查询间交互（self-attention）的空间调制；
  - 查询到图像特征的交叉注意力（cross-attention）几何偏置；
  - 最终高斯生成的局部参考中心。
- **关键技术细节**：
  - **锚点参数化**：使用无约束参数 ρ 经 softplus 激活得到支撑半径 r = softplus(ρ) + ε，保证正数；锚点中心初始化为可学习、场景共享的参数。
  - **锚点感知自注意力**：由锚点中心生成位置编码，注入 token 特征后再进行自注意力，使 token 间的交互依赖于其当前 3D 位置。
  - **锚点到射线交叉注意力**：计算锚点中心到图像 token 对应相机射线的最近距离 D(μ, ℓ)，引入几何偏置 b = -½(D/(σ₀·r))²，并将其加到内容注意力 logits 上。该偏置让查询优先聚合与自身空间位置几何一致的图像证据，半径控制偏好范围。
  - **动态锚点细化**：每层解码后，用轻量级头预测锚点中心和半径的残差更新，使锚点逐步适应输入场景。
  - **锚点中心高斯解码**：最终高斯中心 = 最终锚点中心 + 支撑半径 × 局部偏移，即 μ^G = μ^L + r^L·δ，从而限制同一 token 的高斯分布在局部区域；其余属性（尺度、旋转、颜色、不透明度）由标准头预测。
  - **多层渲染监督**：对中间解码层和最终层同时进行渲染监督，并用可见性正则化约束高斯中心和锚点中心，损失加权按层递增。
- **算法流程**：输入多视角图像 → 图像编码器提取多视角特征（含 Plücker 射线）→ 解码器交替执行锚点感知自注意力和锚点引导交叉注意力，每层更新 token 特征和锚点状态 → 最终层按锚点中心解码高斯组 → 组合所有 token 的高斯组渲染。

## 6. 主要结论与发现

- 显式的 3D 锚点状态能够显著提高查询式前馈 3DGS 的渲染质量：在相同高斯预算下，LocusGS 在 RE10K 和 DL3DV 上均优于 TokenGS，且 1024-token 变体在 RE10K 上已超过使用两倍高斯的 GS-LRM。
- 锚点状态使查询的空间角色更清晰：锚点形成覆盖场景主要结构的粗略空间骨架，半径在不同区域呈现自适应变化（细节区域小半径，稀疏区域大半径）。
- token 级高斯分布明显更紧凑：通过 C_centroid 指标量化，LocusGS 在两个数据集上大幅降低了同一 token 内高斯的分散度。
- 锚点引导的交叉注意力更局部化和视角一致，几何偏置与内容注意力结合后能减少外观歧义。
- 训练收敛更快，验证 PSNR 更高。
- 多层渲染监督能提升性能，监督中间层与最终层是最佳组合。

## 7. 优点

- **问题洞察准确**：直接指出现有查询式 3DGS 中查询缺乏空间责任区的核心问题，并通过可视化证实。
- **方法简洁有效**：将 DAB-DETR 的锚点思想扩展到 3D 场景重建，设计自然且可解释，不引入大量额外参数。
- **几何与内容联合建模**：锚点到射线偏置在注意力中引入几何先验，兼顾内容相似性和几何一致性，符合多视图重建的物理原理。
- **可控对比实验**：选择 TokenGS 作为干净基线，在相同 token 和高斯预算下比较，能够清晰分离空间锚定带来的增益。
- **多维度验证**：不仅报告指标，还通过定性可视化、定量分散度、注意力分解、训练曲线等丰富分析支撑结论。
- **开源性**：提供项目页面，便于复现和交流。

## 8. 不足与局限

- **依赖已知相机位姿**：LocusGS 的锚点到射线偏置依赖于精确的相机内外参，无法直接适用于无位姿（pose-free）输入；位姿有噪声时可能影响鲁棒性。
- **锚点状态过于简单**：每个锚点仅包含中心和标量半径，是各向同性的局部支撑描述，难以精确刻画细长结构或复杂几何区域；论文也承认这一点。
- **算力信息缺失**：未报告训练所需的 GPU 数量、时长和具体算力预算，难以评估方法在资源消耗上的实际成本。
- **并发方法比较有限**：未与 GlobalSplat、C3G 等同时期查询式系统的完整结果进行直接对比，可能影响对不同方法综合性能的全面判断。
- **额外开销**：相比 TokenGS，参数量和前向延迟增加约 10–20%，在部署实时性要求高的场景可能需要权衡。
- **监督复杂性**：多层渲染监督增加了训练复杂度和计算开销，需要对多层输出进行渲染和损失计算。
